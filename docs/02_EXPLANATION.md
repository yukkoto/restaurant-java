# Объяснение кода простыми словами

## С чего начать чтение

Читайте в порядке: `Customer` → `RestaurantOrder` → `OrderStatus` → `Main` → `ConsoleUi` → `OrderService` → `OrderRepository` → `DatabaseManager` → `ExcelExporter`.

Все эти классы лежат в `src/main/java/ru/mirea/restaurant`, в соответствующих подпапках.

## Один пример целиком

Вы выбираете «Заказы → Создать» и вводите клиента, номер стола, состав и сумму.

1. `ConsoleUi` читает строки с клавиатуры. Если вместо номера ввести `abc`, просит число снова.
2. `OrderService.create()` проверяет: существует ли клиент, верен ли стол, заполнен ли состав, допустима ли сумма.
3. Сервис создаёт объект `RestaurantOrder` со статусом `NEW`.
4. `OrderRepository.create()` открывает соединение, выполняет `INSERT` с параметрами.
5. PostgreSQL сохраняет строку и назначает ID и время создания. `RETURNING *` возвращает сохранённую строку.
6. Репозиторий превращает строку в Java-объект, меню показывает результат.

После закрытия Java-программы заказ остаётся в PostgreSQL. При следующем запуске список читается заново.

## Классы и слои

| Класс | Обязанность |
|---|---|
| `Main` | Создаёт нужные объекты, связывает их и запускает меню |
| `Customer` | Хранит ID, имя и телефон одного клиента |
| `RestaurantOrder` | Хранит данные одного заказа |
| `OrderStatus` | Перечисляет пять возможных статусов |
| `ConsoleUi` | Показывает меню и читает ответы |
| `CustomerService` | Проверяет клиента и управляет его операциями |
| `OrderService` | Проверяет заказы, переходы статусов; ищет, фильтрует, сортирует и считает статистику |
| `ReportService` | Запускает экспорт и получает список таблиц |
| `CrudRepository<T>` | Интерфейс: договор о пяти операциях с данными |
| `CustomerRepository`, `OrderRepository` | Выполняют SQL-запросы через JDBC |
| `DatabaseInfoRepository` | Получает названия таблиц из системного представления PostgreSQL |
| `DatabaseManager` | Читает настройки, открывает соединение, объясняет ошибки SQL |
| `ExcelExporter` | Создаёт Excel-файл из переданных списков |
| `BusinessException` | Нарушено правило ресторана |
| `EntityNotFoundException` | Запись не найдена |
| `DataAccessException` | Ошибка подключения или SQL |

Меню не содержит SQL. Репозитории не задают вопросы пользователю. Сервисы не зависят от консоли. Поэтому в КР 2 вместо консольного меню можно подключить JavaFX к тем же сервисам.

## ООП на примерах

**Класс** — описание типа объекта. `Customer` описывает клиента. **Объект** — конкретный клиент, например `new Customer(1, "Анна", "+79000000001")`.

**Конструктор** получает начальные значения и записывает их в поля объекта.

**Инкапсуляция:** поля `private`, к ним нельзя обратиться из другого класса напрямую. Чтение идёт через методы `getName()`, `getId()` и другие. Поля также `final`: готовый объект не меняется. При редактировании сервис создаёт новый объект с тем же ID и передаёт его репозиторию. Сеттеры для задания не обязательны.

**Интерфейс:** `CrudRepository<T>` сообщает, какие методы есть у хранилища: `create`, `findAll`, `findById`, `update`, `delete`. Буква `T` означает «конкретный тип сущности»: для клиентов — `Customer`, для заказов — `RestaurantOrder`.

**Полиморфизм:** в `Main` написано:

```java
CrudRepository<Customer> customers = new CustomerRepository(database);
```

Тип переменной — интерфейс, а фактический объект — `CustomerRepository`. Когда сервис вызывает `customers.findAll()`, Java выполняет реализацию этого метода у фактического объекта. Аналогично `CrudRepository<RestaurantOrder>` работает с `OrderRepository`. `@Override` отмечает реализацию метода интерфейса или переопределение, например `toString()`.

**enum:** `OrderStatus` ограничивает набор статусов. В Java используются `NEW`, `COOKING`, `SERVED`, `PAID`, `CANCELLED`; в меню — русские подписи. Произвольную строку вместо статуса передать в сервис нельзя.

## Бизнес-правила

Все проверки ниже есть в Java-сервисах, а часть дополнительно закреплена ограничениями БД.

1. Имя клиента не пустое, максимум 100 символов.
2. Телефон соответствует `+7` и десяти цифрам; он уникален.
3. Клиент заказа обязательно существует.
4. Стол находится в диапазоне 1–20.
5. Состав заказа не пустой, максимум 500 символов.
6. Сумма больше 0, не больше 99 999 999,99 рубля; точность не более двух значащих дробных цифр.
7. Новый заказ создаётся только со статусом `NEW`.
8. Данные заказа можно редактировать только в статусе `NEW`.
9. Допустимые переходы: `NEW → COOKING → SERVED → PAID`. Из `NEW` или `COOKING` можно перейти в `CANCELLED`. Другие переходы, в том числе повторная установка того же статуса, запрещены.
10. Удалять заказ можно только в статусе `NEW` или `CANCELLED`.
11. Нельзя удалить клиента, у которого есть хотя бы один заказ.

Суммы хранятся в `BigDecimal`, потому что `double` может давать погрешности десятичных вычислений. В PostgreSQL используется `NUMERIC(10,2)`. При выводе в Excel сумма превращается в числовую ячейку.

## Коллекции и Stream API

- `List` / `ArrayList` хранят списки объектов, прочитанных из базы.
- `Set` / `HashSet` хранят ID клиентов, найденных по имени, без повторений.
- `Map` / `LinkedHashMap` хранят пары «название показателя — значение» и сохраняют порядок вывода.
- `stream()` начинает последовательную обработку списка.
- `filter(...)` оставляет подходящие записи.
- `sorted(...)` сортирует, `Comparator` задаёт правило сравнения.
- `toList()` собирает результат в список.

Например:

```java
return orders.findAll().stream()
        .filter(o -> o.getStatus() == status)
        .toList();
```

`o -> ...` — короткая функция: «для каждого заказа o проверить условие». Сама фильтрация выполняется в Java, как допускает задание. Источник записей всё равно PostgreSQL. Для большой реальной базы фильтрацию и постраничную загрузку стоило бы перенести в SQL.

## JDBC и SQL

**JDBC** — стандартный способ работы Java с базой данных. Библиотека PostgreSQL JDBC Driver связывает этот интерфейс с PostgreSQL.

- `Connection` — открытое соединение с базой.
- `PreparedStatement` — SQL-запрос с параметрами.
- `ResultSet` — строки результата запроса; `rs.next()` переходит к следующей строке.
- `executeQuery()` возвращает строки (`SELECT`, а в PostgreSQL также `INSERT ... RETURNING`).
- `executeUpdate()` возвращает число изменённых строк (`UPDATE`, `DELETE`).
- `try-with-resources` автоматически закрывает соединение, запрос и результат даже при исключении.

`Statement` обычно выполняет готовый SQL-текст. `PreparedStatement` позволяет поставить `?` и отдельно передать значения:

```java
PreparedStatement ps = connection.prepareStatement("SELECT * FROM customers WHERE id = ?");
ps.setInt(1, id);
```

Значение параметра не становится частью SQL-кода. Например, кавычка в имени клиента не ломает запрос. В приложении нет склейки SQL с пользовательским вводом.

В `map()` поля `ResultSet` преобразуются в Java-объект. В `fill()` поля объекта записываются в параметры запроса. Это просто вспомогательные методы, чтобы не дублировать один и тот же код создания и изменения.

## База данных

`PRIMARY KEY` — уникальный ID строки. `IDENTITY` автоматически выдаёт новые ID.

`FOREIGN KEY` у `restaurant_orders.customer_id` ссылается на `customers.id`. Это связь «один ко многим». У клиента может быть ноль или много заказов, у заказа — ровно один клиент.

`NOT NULL` запрещает отсутствие значения. `UNIQUE` запрещает повтор телефона. `CHECK` проверяет допустимые значения, например номер стола. `ON DELETE RESTRICT` запрещает удалять клиента, если на него ссылаются заказы.

В БД хранятся английские коды статусов, а не их номера в меню. Выручка в статистике — сумма только заказов `PAID`. Начальная выручка: 1800 + 700 + 550 = **3050 рублей**.

## Исключения и ввод

Сервис сообщает о нарушении правила с помощью `throw new BusinessException(...)`. Меню перехватывает его в `catch`, печатает понятное сообщение и продолжает работу.

Ошибку ввода числа обрабатывает `NumberFormatException`, даты — `DateTimeParseException`. Ошибки JDBC перехватываются как `SQLException` и превращаются в `DataAccessException` с сохранением исходной причины. Если стандартный ввод закрыт, программа корректно завершает меню.

## Экспорт

`ReportService` получает списки из базы и передаёт их `ExcelExporter`. Библиотека Apache POI создаёт `XSSFWorkbook`, листы, строки и ячейки. `workbook.write()` записывает полноценный `.xlsx`. Это не текстовый файл с изменённым расширением.

## Что намеренно сделано просто

Нет Spring, Hibernate, Lombok, пула соединений и дополнительной сущности блюда. Соединение открывается для каждой операции. Правила переходов статуса выражены обычным `switch`. Сумму вводит оператор. Такая структура покрывает данное задание и позволяет поэтапно учиться.

При одновременной работе нескольких операторов понадобятся транзакции и защита от конфликтующих изменений. В текущей учебной версии предполагается один оператор.
